# RCA — hi.tours / www.hi.tours TLS handshake failure

## Problem statement
User reports `hi.tours` (and `www.hi.tours`) is not working. `curl https://hi.tours/` and `curl https://www.hi.tours/` fail immediately with `OpenSSL ... sslv3 alert handshake failure` (HTTP 000). DNS resolves `hi.tours` to `172.66.2.113` (a Cloudflare range), so DNS is fine but the TLS handshake is rejected at the edge. Preview app works; recent code changes were frontend-only (Meta Pixel, Google Ads tags, /thank-you redirect) and do not affect routing.

## What I checked
- `describe_deployment_state` for deployment `tourlane-rebuild` (f125080c-384d-4c24-a41b-bef333c07af8).
- `list_domains` — custom domains attached to the deployment.
- `check_domain_status` — live DNS/binding check per custom domain.

## Evidence
1. **Deployment is suspended/torn down for non-payment.**
   `describe_deployment_state` returns:
   - `"deployment_status": "deleted"`
   - `"suspension_reason": "negative_credit"`
   - `"billing_plan": "monthly"`
   The last deploy run (`a2de6017-...`, 2026-10-19) itself succeeded, so this is NOT a code/build/deploy failure — the deployment was later suspended due to a negative credit balance.

2. **No custom domain is bound to the deployment.**
   - `list_domains` → `"domains": []`
   - `check_domain_status` → `"domains": []`
   There is currently **no custom-hostname binding and no SSL certificate** for `hi.tours` or `www.hi.tours` on our Cloudflare edge.

## Root cause
The deployment `tourlane-rebuild` has been **suspended and torn down because the account credit balance went negative** (`suspension_reason: negative_credit`, `deployment_status: deleted`). When the deployment was suspended, its Cloudflare custom-hostname bindings for `hi.tours` and `www.hi.tours` were removed, so no SSL certificate is provisioned/served for those hostnames anymore.

DNS still points at Cloudflare (`172.66.2.113`), so the client reaches the edge — but because there is no custom hostname / certificate bound for `hi.tours`, the edge has no cert to present and **rejects the TLS handshake** (`sslv3 alert handshake failure`, HTTP 000). This is a certificate/binding absence, not a Cloudflare SSL-mode conflict and not a DNS problem.

The recent frontend-only code changes are unrelated — they do not touch routing, domains, or TLS.

## Fix (user actions, in order)
1. **Settle the negative credit balance / restore the subscription.** This is the blocker — while the account is in `negative_credit` the deployment stays suspended (`deleted`) and nothing (domain, SSL, app) can be restored. Nothing else below will take effect until this is cleared.
2. **After the deployment is restored, re-add the domains** in Deployment Panel → Domains: add both `hi.tours` and `www.hi.tours`. Copy the DNS records shown there verbatim into the registrar/Cloudflare if they differ, and wait for verification + SSL certificate issuance to complete. Once the custom hostname is bound and the cert is active, the TLS handshake will succeed.

## Not the cause (ruled out)
- Not a code/build/deploy regression — the active run succeeded and frontend-only changes don't affect routing.
- Not a DNS-not-pointed issue — the name already resolves to Cloudflare.
- Not a Cloudflare SSL-mode conflict — the handshake fails because there is no bound custom hostname/cert at all (domains list is empty), which traces directly to the suspension.
